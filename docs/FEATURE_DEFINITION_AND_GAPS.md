# 快乐学园（happy-learning）功能诊断与高价值功能定义

> 文档类型：功能定义与完善要求（Functional Definition & Completion Requirements）
> 视角：项目总监（MVP 专家团）对现有代码库的诊断式分析
> 目标读者：产品/架构/前端负责人；不面向直接编码，聚焦"做什么、做到什么程度、接入哪里、缺什么"
> 技术基线：React 18 + Vite 5 + CSS Modules + Context（双 Context + slice reducer）；内容对齐 2022 课标与统编教材

## 一、项目现状总览（已具备的能力）

| 维度 | 现状 | 结论 |
|------|------|------|
| 架构 | 状态层拆为 `AppStateContext` / `AppActionsContext` 双 Context；5 个 slice reducer（progress/parent/rewards/review/profile）；`selectors.ts` 集中派生；`storage.ts` 含 `migrate(v1→v2)` 与字段守卫 | **优良**，是本项目最大亮点 |
| 数据对齐 | `content.js` + `grade.js`（1690 行）覆盖 1-6 年级、3 主科；英语一/二年级"预备级"已用 `note` 弱化提示 | **严谨**，符合课标 |
| 练习引擎 | `ExerciseEngine.jsx`：逐题作答、判分、解析、错题复习模式、`normalizeQuestion` 防御残缺题 | **完善** |
| 游戏化 | 积分/等级/徽章（9 枚+彩蛋）、连续打卡、Leitner 间隔重复错题本、撒花庆祝层、吉祥物心情 | **到位** |
| 健壮性 | 全局+路由级双重 ErrorBoundary、空态全覆盖、`prefers-reduced-motion` 降级 | **良好** |
| 测试 | 仅 `state/` 有 Vitest（score/reducer）；组件层 0 测试 | **薄弱** |

**核心短板（一句话）**：架构成熟，但存在若干"半成品死功能"（护眼提醒、主题皮肤）、缺少真实语音朗读、以及一处 emoji P0 风险与导航配置漂移。

## 二、核心目标与用户场景

### 2.1 核心目标
为小学 1-6 年级儿童提供"学—练—玩—复习—成长"闭环的轻量学习前端，内容严格对齐国内现行课标与统编教材，并以游戏化激励维持学习黏性；同时为家长提供监督与设置面板。

### 2.2 用户场景

| 角色 | 关键场景 | 当前支撑度 |
|------|----------|------------|
| 儿童（1-6 年级） | 按学科/年级学习、做练习判分、看动画视频、玩记忆游戏、复习错题、查看成长墙与奖励 | 高（缺"真实朗读""收藏""多关卡"） |
| 家长 | 查看周报、设置每日时长/护眼/音效/青少年模式/PIN、了解孩子进度 | 高（护眼开关无效、PIN 无校验/找回） |

## 三、高价值低风险提示（筛选结果）

筛选原则：**业务价值高 × 实现风险低 × 不引入新技术栈 × 显著补齐体验或系统能力闭环**。

| 排序 | 功能点 | 现状 | 价值 | 风险 | 理由 |
|------|--------|------|------|------|------|
| 1 | 语音朗读 / TTS 跟读 | 未实现（仅手动打卡） | 高 | 低 | 浏览器原生 `SpeechSynthesis`（zh-CN），零依赖，天然契合"朗读"刚需 |
| 2 | 护眼提醒真实弹窗 | 半成品（开关在、逻辑无） | 高 | 极低 | 已有 `eyeRest` 开关 + `studySeconds` 累计，补定时器+提示即可 |
| 3 | 主题皮肤应用 | 半成品（奖励在、应用无） | 中 | 低 | 消费 `redeemedRewards` 中的 `skin-sunset`，切换 `:root` 变量 |
| 4 | 消除 emoji P0 风险 | 违规（MATCH_WORDS 用 emoji） | 中 | 低 | 用 `Icon` 字形或纯文字替代 `☀️🌙⭐🍎📚🐱` |
| 5 | 用户自定义收藏夹 | 未实现（仅徽章展示册） | 中 | 低 | 新增 `favorites` 字段 + 课文/古诗"★收藏" |
| 6 | 错题举一反三 | 未实现（仅原题重练） | 中 | 低 | 复用 `WrongEntry.pointId` 溯源，按知识点推同 point 他题 |
| 7 | 导航配置统一 + `/videos` 入导航 | 不一致 | 中 | 极低 | 单一数据源，提升可发现性与专业度 |
| 8 | 家长 PIN 校验/找回 | 半成品（无长度校验/找回） | 低 | 低 | 强制 4-6 位、提供找回通道 |

> 排序 1-4 建议作为第一批次（高价值+极低/低风险，且均不破坏存量）；5-8 为第二批次。

## 四、精选功能定义与完善要求（核心交付）

> 每条包含：功能定义与预期行为 / 输入-输出规范 / 边界条件 / 集成方式 / 需补全逻辑·错误处理·状态管理 / 验收要点。

### 4.1 语音朗读 / TTS 跟读

- **功能定义与预期行为**
  - 在"课文朗读打卡"（TextbookPage）与古诗/识字内容旁提供「听一听」按钮；点击后使用浏览器 TTS 以普通话（zh-CN）朗读选中文本。
  - 提供"朗读中"视觉态（高亮当前句/字形、按钮禁用）；可中断（再次点击停止）；朗读完成后自动勾选 `textRead` 打卡项（可选，默认不自动勾选，需用户确认）。
  - 儿童友好：语速适中、可重复；不依赖网络。

- **输入-输出规范**
  - 输入：待朗读文本字符串（来自 `LESSONS[].texts[].paragraphs` 或 `GRADE_LEARNING` 诗文）、调用方学科/年级（用于选择发音人或参数）。
  - 输出：音频播报（无结构化返回）；UI 状态 `speaking: boolean`、`currentParaIndex?`。

- **边界条件**
  - 浏览器不支持 `window.speechSynthesis` → 按钮禁用并提示"当前设备暂不支持朗读"。
  - 朗读中途用户切走/卸载组件 → 组件卸载时强制 `cancel()`，避免串音。
  - 连续快速点击 → 用 `busy` 锁，禁止并发实例。
  - 中文多音字（如"行""重"）→ 接受基础朗读，不要求完美；可预留 `lang` 参数。

- **集成方式（接入点）**
  - 新建 `utils/speech.js`（封装 `speechSynthesis` + `SpeechSynthesisUtterance`，统一 `zh-CN`、音量与速率）。
  - 在 `TextbookPage.jsx` 朗读区与 `GradeLearning`/`LessonTexts` 诗文展示处挂载「听一听」按钮。
  - 与现有 `sound.js`（Web Audio 音效）并列，均属"声音能力"，但职责分离（一个朗读、一个反馈音）。

- **需补全的逻辑 / 错误处理 / 状态管理**
  - 逻辑：`getVoices()` 异步加载，需监听 `voiceschanged` 事件后再选音；`onend` 回调复位 `speaking`。
  - 错误处理：TTS 异常（`onerror`）静默降级为文本高亮无语音；不阻断页面。
  - 状态管理：**不进全局 AppState**（属瞬时 UI 态），用组件局部 `useState` 即可；若需跨页延续"朗读偏好（语速/是否自动勾选）"，可纳入 `parent` 或新增 `prefs` 子域（需走 Spec 变更评估）。

- **验收要点**：支持的设备点击可朗读且可停止；不支持的设备按钮禁用；卸载无串音；不引入新依赖。

### 4.2 护眼提醒真实弹窗（补全半成品）

- **功能定义与预期行为**
  - 家长开启"护眼提醒"（`parent.eyeRest=true`）后，累计学习每满 20 分钟，弹出一个非阻断式提醒（建议轻量 toast/模态，非全屏遮挡），提示"休息一下，看看远处"。
  - 提醒可"稍后/知道了"关闭；下一次计时从 0 重新累计。关闭后不重复打扰同一时段。

- **输入-输出规范**
  - 输入：`parent.eyeRest`（开关）、`studySeconds` / `todayStudySec`（累计时长）。
  - 输出：提醒 UI 出现一次；内部计时器状态（`lastRestAt` 时间戳）。

- **边界条件**
  - `eyeRest=false` → 完全不触发。
  - 单日学习时长跨 midnight → 以 `todayDate` 重置计数（复用已有 `todayDate`/`lastActiveDate` 机制）。
  - 提醒弹出时恰逢青少年模式夜间锁（22:00–6:00）→ 护眼提醒优先级低，不叠加打扰。
  - 标签页后台（`visibilitychange`）→ 暂停计时，回到前台恢复，避免后台虚增。

- **集成方式（接入点）**
  - 在 App 根层（如 `App.jsx` 或新建 `EyeRestWatcher`）挂载一个监听器，订阅 `studySeconds` 增量。
  - 复用 `CelebrationLayer` 的 toast 通道或新增轻量 `EyeRestToast`，避免与撒花庆祝冲突（庆祝用 confetti，护眼用静态提示）。

- **需补全的逻辑 / 错误处理 / 状态管理**
  - 逻辑：当前 `eyeRest` 是**死字段**——全代码无定时器/弹窗读取它。需补：累计阈值检测（20min）、触发后复位计数、去重（同一窗口仅提醒一次）。
  - 状态管理：阈值计数建议用 `todayStudySec` 派生或新增 `lastEyeRestMinute` 字段（若需持久化跨刷新则不丢进度）。
  - 错误处理：弹窗渲染失败不得影响学习流；用 ErrorBoundary 兜底。

- **验收要点**：开启后学习满 20 分钟出现一次提醒；关闭后重置；开关关闭完全静默；不阻断主流程。

### 4.3 主题皮肤应用（补全半成品）

- **功能定义与预期行为**
  - 奖励商店中 `skin-sunset`（`kind:'theme'`）被兑换后，界面整体切换为"温暖夕阳"配色（一组 CSS 变量覆盖），并在成长中心/设置可见"当前皮肤"状态。
  - 支持"恢复默认"；可扩展为多个主题（夕阳/森林/海洋），但本期仅落地震荡一个。

- **输入-输出规范**
  - 输入：`redeemedRewards` 中存在的 `skin-*` id。
  - 输出：`<html>` 或根容器上挂载 `data-theme="sunset"` 属性；`index.css` 中对应 `:root[data-theme="sunset"]` 变量覆盖块生效。

- **边界条件**
  - 未兑换任何皮肤 → 维持默认主题（无 `data-theme`）。
  - 兑换后切换设备/刷新 → 从 `redeemedRewards` 复原主题（持久化已具备）。
  - 主题色需满足对比度（复用 `--c-*-ink` 文字变体机制），不得破坏可读性（符合 P0 颜色规范，禁止紫粉渐变）。

- **集成方式（接入点）**
  - 在 `AppContext` 初始化或 `useEffect` 中读取 `redeemedRewards`，对 `skin-*` 设 `document.documentElement.dataset.theme`。
  - 在 `index.css` 增加 `[data-theme="sunset"]` 变量块（仅改色值，不引入新机制）。
  - `rewards.ts` 的 `REDEEM` 逻辑无需改（已写入 `redeemedRewards`），**仅补"消费"侧**。

- **需补全的逻辑 / 错误处理 / 状态管理**
  - 逻辑：当前 `kind==='theme'` 无任何代码消费 → 兑换"花了积分却无变化"。需补主题应用与"恢复默认"入口。
  - 错误处理：未知 `skin-*` id → 忽略，回退默认，不报错。
  - 状态管理：主题由 `redeemedRewards` 派生，**不新增状态字段**（保持单一数据源）。

- **验收要点**：兑换夕阳皮肤后界面即时变色并跨刷新保持；恢复默认生效；不破坏既有 Token 对比度。

### 4.4 消除 emoji P0 风险（合规修复）

- **功能定义与预期行为**
  - 记忆配对游戏（GameCenter）的牌面当前用 `MATCH_WORDS` 的 emoji（`☀️🌙⭐🍎📚🐱`）。改为使用项目锁定的 `Icon` 字形（如 book/star/sun/moon/apple/cat 等语义图标）或纯文字标签，确保跨端一致，消除 P0 违规。

- **输入-输出规范**
  - 输入：`MATCH_WORDS` 条目（原含 `emoji` 字段）。
  - 输出：渲染为 `<Icon name=... />` 或 `<span>{label}</span>`，不再渲染 emoji 字符。

- **边界条件**
  - `Icon` 库无对应字形时 → 用文字 label 兜底，不引入新图标库（遵守"锁定一套不混用"）。
  - 游戏配对逻辑（对比 `pair` 键）不变，仅改展示层。

- **集成方式（接入点）**
  - 修改 `content.js` 的 `MATCH_WORDS`：去掉 `emoji` 字段或改为 `icon`/`label`；修改 `GameCenter.jsx:114` 渲染逻辑。
  - 复用现有 `Icon.jsx`（项目已明确"不用 emoji"铁律）。

- **需补全的逻辑 / 错误处理 / 状态管理**
  - 无状态变更；纯展示层替换。
  - 可用 emoji 正则扫描全仓做回归校验（见 P0 规则）。

- **验收要点**：全仓无 emoji 作功能/牌面图标；配对游戏视觉与交互不变；跨端一致。

### 4.5 用户自定义收藏夹

- **功能定义与预期行为**
  - 儿童可在课文、古诗、错题、视频等条目上点击「★收藏」，在"我的收藏"聚合页查看与快速跳转；收藏为个人偏好，不影响学习进度。
  - 与现有 `CollectionAlbum`（徽章/奖励展示册）区分：后者是系统成就展示，前者是用户主动收藏。

- **输入-输出规范**
  - 输入：被收藏对象的 `{ kind: 'text'|'poem'|'wrong'|'video', key, title, subject?, grade? }`。
  - 输出：`favorites: FavoriteItem[]`（去重，按收藏时间倒序）；聚合页列表。

- **边界条件**
  - 重复收藏同一对象 → 幂等（再次点击为取消）。
  - 被收藏内容后续被内容更新/移除 → 收藏项仍可展示历史标题，点击跳转时若目标不存在则降级提示。
  - 与错题本关系：错题可一键"加入收藏"，但收藏不反写错题数据。

- **集成方式（接入点）**
  - 新增 `state` 字段 `favorites`（数组或 `Record<key, FavoriteItem>`），新增 action `TOGGLE_FAVORITE`。
  - 在 `textbook.js` 诗文区、`WrongQuestionCenter`、`VideoLibrary` 条目加「★」按钮（复用 `Icon` star 字形）。
  - 新增"我的收藏"页或在 GrowthCenter 增加 Tab；`storage.ts` 增加 `favorites` 字段守卫与 `migrate` 兼容。

- **需补全的逻辑 / 错误处理 / 状态管理**
  - 逻辑：新增 slice reducer（或并入 `profile` 域）；`selectors` 提供 `favoriteByKey` 查询。
  - 错误处理：非法/空 key 忽略；上限保护（如 200 条，超出提示清理）。
  - 状态管理：`favorites` 持久化落盘（复用现有 `saveState` 机制）。

- **验收要点**：可收藏/取消任意支持条目；聚合页正确罗列并可跳转；刷新后保留；不污染学习数据。

### 4.6 错题举一反三

- **功能定义与预期行为**
  - 在错题本/复习中心，对每道错题除"原题重练"外，提供「相似题 / 举一反三」：基于该题 `pointId` 溯源，从 `GRADE_LEARNING[grade].subjects[subjectId].points` 同 point 中取其他练习题推给儿童，强化同一知识点。

- **输入-输出规范**
  - 输入：错题 `WrongEntry { subject, grade, pointId, pointTitle }`。
  - 输出：同 point 下 `exercises` 中**非当前错题**的若干题（最多 N 道，如 3）；无同源题时降级为"暂无相似题，建议复习原题"。

- **边界条件**
  - 旧链路错题仅存 `true`（无 pointId）→ 无法溯源，降级为原题重练，不报错。
  - 同 point 题目不足 → 取全部可用，不足部分不补足。
  - 推荐题已被掌握/答对 → 可从计划剔除（可选）。

- **集成方式（接入点）**
  - 复用 `getGradeLearning(grade).subjects[subjectId].points.find(p=>p.id===pointId).exercises`。
  - 在 `WrongQuestionCenter.jsx` 或 `ExerciseEngine` 复习模式增加"举一反三"入口，复用现有判分与 `score.ts`。
  - 不新增数据表，仅消费既有 `GRADE_LEARNING` 结构。

- **需补全的逻辑 / 错误处理 / 状态管理**
  - 逻辑：新增 `getSimilarQuestions(wrongEntry)` 纯函数（建议放 `data/` 或 `state/helpers`）。
  - 错误处理：溯源缺失/无结果 → 优雅降级；不阻断复习流。
  - 状态管理：推荐为瞬时计算，不持久化（除非要做"已推过"去重，可加 `reviewSchedule` 扩展）。

- **验收要点**：有 pointId 的错题能推出同源他题；无溯源错题优雅降级；复用既有判分不重复造轮子。

### 4.7 导航配置统一 + `/videos` 入导航（快速修复）

### 4.8 家长 PIN 校验与找回（第二批次，低风险）

- **功能定义与预期行为**
  - 设置/修改家长 PIN 时强制 4–6 位数字格式校验；提供"忘记 PIN"的找回通道（如验证后重置，或通过已绑定的家长邮箱/安全问题——本期可用"二次确认清空"兜底）。
  - 青少年模式解锁、家长面板进入均需 PIN。

- **输入-输出规范**
  - 输入：PIN 字符串（4-6 位数字）。
  - 输出：校验通过/失败；`parent.parentPin` 更新。

- **边界条件**
  - 非数字/长度不符 → 即时校验错误提示，禁止提交。
  - 连续错误尝试 → 可加短暂锁定（防暴力，可选）。
  - 找回流程：当前无绑定邮箱，提供"确认后重置为未设置"的安全路径。

- **集成方式（接入点）**
  - 在 `ParentPanel.jsx` 的 PIN 输入处加 `pattern`/受控校验；`MinorModeGate` 解锁逻辑复用同一校验。

- **需补全的逻辑 / 错误处理 / 状态管理**
  - 逻辑：当前 `placeholder` 提示但无强制校验 → 加受控校验 + 找回入口。
  - 错误处理：找回操作需二次确认（`window.confirm` 或模态），防误触。

- **验收要点**：PIN 强制 4-6 位数字；找回通道可用且安全；不影响既有解锁。

## 七、总结

happy-learning 是一个**架构成熟、内容对齐严谨、游戏化与健壮性到位**的儿童教育前端。本批建议聚焦"把已有半成品变成真功能 + 补一项高价值原生能力 + 消除合规风险"：

- **立刻做（零/极低风险）**：emoji P0 修复、导航统一、`/videos` 入导航、护眼提醒弹窗、主题皮肤应用。
- **高价值原生能力**：语音朗读 TTS（显著补齐"朗读"真实体验，零依赖）。
- **体验增强（第二批）**：收藏夹、错题举一反三、家长 PIN 校验。

以上功能定义均不含实现代码细节，按"功能定义—输入输出—边界—集成点—缺什么"五段式给出，可直接作为开发侧的验收契约。
