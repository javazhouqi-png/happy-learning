### 1.3 "顶级产品"的杠杆判断
本产品对比免费 AI / 通用学习 App 的护城河不是"题多"，而是三件事：
1. **诊断可信度**（家长周报升级为诊断报告：哪里不会、怎么陪）—— 这是 PRD 明确的核心资产。
2. **个性化与分龄**（自适应难度 + 年级/学段严格分层 + 拼音标注）。
3. **沉浸互动**（闪卡、口算闯关、听写跟读、自绘动画课）。

下面 6 个功能点即围绕这三点筛选，兼顾"地基补全（消除坏 UI / 合规）"与"护城河（差异化）"。

---

## 二、二、筛选原则

- **地基补全**：消除已存在但渲染/逻辑残缺的功能（多题型坏 UI、年级入口缺失），是可信度底线。
- **护城河差异化**：诊断报告、互动模式、自适应——让产品感觉"比通用工具强"。
- 全部满足：业务价值高 × 实现风险低 × 不引入新技术栈 × 不破坏存量。

## 三、精选功能定义（验收契约）

### N1 · 多题型引擎真正落地（连线 / 填空 / 笔顺）

- **功能定义与预期行为**
  - 答题引擎按 `q.type` 分发渲染与判分：`single`（单选）、`fill`（选字/选词填空，仍是选项式）、`connect`（连线配对）。connect 题型展示左右两列词条，儿童点击配对，全部正确即过关。
  - 不同题型共用既有"逐题作答 → 判分 → 解析 → 错题记录 → 举一反三"主流程，仅渲染层与 scorer 分支不同。

- **输入-输出规范**
  - 输入：题目对象（`type` + 对应字段：`options/answer` 或 `pairs`）。
  - 输出：渲染对应题型 UI；`score.ts` 返回 `{ correct, ... }`；错题记录照常带 `type/pointId`。

- **边界条件**
  - `type` 未注册 → 引擎兜底渲染为 single 并打 `console.warn`（不白屏）。
  - connect 配对允许撤销/重选；半完成状态不算分。
  - 旧档/外部题目缺 `type` → 默认 `'single'`（沿用 `score.ts` 现有兜底）。

- **集成方式（接入点）**
  - 消费 `score.ts` 已搭的 `REGISTRY`：新增 `connect` Scorer（按 `pairs` 左右匹配判定）。
  - `ExerciseEngine.jsx` 增加题型分发：`{q.type === 'connect' ? <ConnectQuiz/> : <OptionsQuiz/>}`；`OptionsQuiz` 兼容 single/fill。
  - **实现前先跑一次"全题型抽样渲染"**：遍历 `QUIZZES` + `GRADE_LEARNING` 确认是否有 connect 题已进入 `getQuiz` 返回集（若有，则本项为必修，否则存在潜伏坏 UI）。

- **需补全逻辑 / 错误处理 / 状态管理**
  - 逻辑：`registerScorer('connect', ...)`；`QuestionType` 联合补 `'connect'`。
  - 状态管理：题型为题目属性，不新增全局字段；connect 作答态用组件局部 `useState`（已存在 `answers` 结构需支持数组/对象值）。

- **验收要点**：connect 题可正常渲染、配对、判分、进错题；全题型抽样无白屏/空选项；不破坏 single/fill 既有流程；tsc/lint 通过。

### N2 · 每日学习任务单（今日三件事）

- **功能定义与预期行为**
  - 新用户/每日首开首页时，首屏呈现"今日三件事"：① 新学 1 个知识点（按当前年级/学科推荐未掌握点）、② 复习 N 道错题（取 Leitner 到期或错次最高）、③ 1 个挑战（小游戏/口算/朗读打卡）。
  - 每件可一键进入对应模块；完成后标记，当日不再重复派发；可查看"明日预告"。

- **输入-输出规范**
  - 输入：`state.grade`、`derived.mastery`、`reviewSchedule`（错题本）、`favorites`、打卡记录。
  - 输出：`dailyTasks: { date, items: Task[] }`（瞬时或持久化均可；建议持久化 `lastTaskDate` 防重复派发）。

- **边界条件**
  - 无错题/无学习记录 → 推荐"新学 + 挑战"，不强制错题项。
  - 跨日（日期变更）→ 重新派发，旧任务归档为历史。
  - 同日内重复打开 → 读缓存任务，不重派。

- **集成方式（接入点）**
  - 新增轻量纯函数 `buildDailyTasks(state, derived)`（放 `state/helpers.ts` 或 `utils/`）。
  - 在 `Home.jsx` 首屏插入 `DailyTaskCard` 组件（复用现有 Card/Button/Icon 体系）。
  - 与挑战/复习/新学模块通过现有路由或 `actions` 跳转衔接。

- **需补全逻辑 / 错误处理 / 状态管理**
  - 逻辑：推荐算法用"未掌握点优先 + 错题优先级 + 随机挑战"三源合并；不依赖后端。
  - 状态管理：建议 `state.daily = { date, items, doneMap }`；`migrate` 增加守卫；可选持久化。
  - 错误处理：推荐源为空 → 降级为"自由探索"引导，不报错。

- **验收要点**：新用户首屏 100% 见"今日三件事"且每件可进入；完成态可标记；跨日重新派发；不破坏首页其余内容。

### N3 · 家长周报升级为诊断报告

- **功能定义与预期行为**
  - 家长空间一屏内列出"本周 3 个薄弱知识点 + 3 条今晚 5 分钟陪学动作"，并可导出图片 / 打印。薄弱点由错题本 `pointId` 聚合（错次高、掌握度低者优先）；陪学动作由知识点 `why/scene`（来自 `GRADE_LEARNING`）生成可执行建议。
  - 这是对比免费 AI 的**核心差异化资产**：把"他哪里不会、我怎么讲"落到纸面。

- **输入-输出规范**
  - 输入：本周 `wrongBySubject`（带 `pointId/pointTitle/grade`）、`derived.mastery`、各知识点 `analysis/scene/why` 文案。
  - 输出：诊断报告对象 `{ weakPoints: {title, subject, grade, wrongCount, advice}[], actions: string[] }`；导出为 PNG/打印视图。

- **边界条件**
  - 本周无错题 → 显示"本周暂无明显薄弱点，保持节奏"，不编造数据（诚实边界）。
  - 知识点文案缺失 → 用通用建议兜底（"复习相关课文 + 做 3 道同类练习"）。
  - 导出失败（如 canvas 受限）→ 降级为"复制文本"按钮。

- **集成方式（接入点）**
  - 扩展 `ParentWeeklyReport.jsx`：新增 `diagnose(state, derived)` 纯函数（复用 `grade.js` 知识点文案）。
  - 导出：用原生 `canvas` 绘制报告卡或 `window.print()` + 打印样式（不引第三方库）。
  - 复用错题四溯源字段（已在 `exercise.ts` 落库），零返工。

- **需补全逻辑 / 错误处理 / 状态管理**
  - 逻辑：按 `pointId` 聚合错次 → 取 Top3；`advice` 映射 `GRADE_LEARNING` 的 `scene/why`。
  - 状态管理：报告为派生计算，不持久化（每次进入实时算）；导出仅客户端。
  - 错误处理：聚合为空 → 友好空态；不影响其余家长面板。

- **验收要点**：家长空间一屏见"3 薄弱点 + 3 陪学动作"；建议源自真实错题与知识点文案；可导出/打印；无错题时诚实空态。

### N4 · 错题↔知识点闭环（分组 + 跳回）

- **功能定义与预期行为**
  - 错题本按知识点（`pointId/pointTitle`）分组展示，每组显示错次与掌握趋势；每组提供"跳回教材解析"与"做同类练习（举一反三）"入口，形成"错在哪 → 为什么 → 怎么巩固"闭环。
  - 与 N3 诊断报告、4.6 举一反三共享数据源，不重复造轮子。

- **输入-输出规范**
  - 输入：`wrongBySubject`（带 `pointId/pointTitle`）、`getGradeLearning(grade).subjects[s].points`。
  - 输出：分组后的错题视图；每组含跳转动作。

- **边界条件**
  - 旧链路错题仅存 `true`（无 pointId）→ 归入"未分类"组，仍可重练，不报错。
  - 跳回目标（教材/练习）不存在 → 降级提示，不崩溃。

- **集成方式（接入点）**
  - 改造 `WrongQuestionCenter.jsx`：新增 `groupByPoint(wrongList)` 纯函数；分组头部加 `Link` 到 `TextbookPage`/`SubjectPage` 对应知识点（复用现有路由）。
  - 复用 4.6 的 `getSimilarQuestions` 作为"同类练习"入口。

- **需补全逻辑 / 错误处理 / 状态管理**
  - 逻辑：分组聚合 + 排序（错次降序）；去重（同 pointId 多错次合并为一条带计数）。
  - 状态管理：纯派生，无新增字段。

- **验收要点**：错题按知识点分组且错次可见；每组可跳回教材/做同类练习；旧错题优雅降级；不破坏既有复习流。

### N5 · 互动学习模式（闪卡 / 口算闯关 / 听写跟读）

- **功能定义与预期行为**
  - 在游戏中心新增两类轻互动：① **闪卡**：字词/单词卡面翻转记背，支持"认识/不认识"分流进错题；② **口算闯关**：计时连算，实时计分与连击；③ **听写跟读**：复用 TTS 播放词，儿童跟读（不评分，仅陪练）。
  - 目标：丰富低龄学生参与度，对标"游戏化学习"顶级体验；与积分/徽章体系打通。

- **输入-输出规范**
  - 输入：`LESSONS` 字词、`GRADE_LEARNING` 单词/算式、TTS 文本。
  - 输出：互动态 UI + 积分/连击；"不认识"的词可一键入收藏或错题。

- **边界条件**
  - 听写跟读无麦克风评分（诚实边界）→ 仅播放 + 自主跟读，不计分不造假。
  - 口算计时到时 → 结算并撒花，不强制完成。
  - 移动端触摸配对需避免误触（复用现有按钮规范）。

- **集成方式（接入点）**
  - `GameCenter.jsx` 增加模式切换（记忆配对 / 闪卡 / 口算）；新增 `FlashCard.jsx` / `ArithmeticChallenge.jsx`（或合并为 `StudyGames`）。
  - 复用 `useApp()` 的积分/收藏/错题 actions。

- **需补全逻辑 / 错误处理 / 状态管理**
  - 逻辑：闪卡分流（认识→下一张；不认识→标记）；口算随机出题（受年级约束，复用 `getQuiz` 算式题或内置口算生成器）。
  - 状态管理：游戏态局部 `useState`；积分走现有 `addPoints`。

- **验收要点**：三种互动均可玩、计分给积分；闪卡"不认识"可入错题/收藏；听写不造假评分；移动端可触。

### N6 · 全站年级分层入口统一 + 分龄护栏

- **功能定义与预期行为**
  - 在 `SubjectPage` 与学习中心提供**常驻且明确的年级切换控件**（不在全局顶栏，避免低龄误触）；切换后全站内容按 `state.grade` 过滤，已做题/掌握度保留不清零。
  - 英语一/二年级明确标注"预备级听说启蒙"，三年级起标注"国家统一起始年级"，落实分龄内容合规（未成年人模式要求）。

- **输入-输出规范**
  - 输入：`state.grade`、`setGrade` action、各年级 `GRADE_LEARNING` 与 `english.note`。
  - 输出：过滤后的学科内容 + 分龄口径标注。

- **边界条件**
  - 切换年级不清除错题/掌握度（仅切换内容范围，沿用 `quizByGrade` 独立维度）。
  - "先随便看看"跳过态 → 按一年级呈现并常驻"设置年级"入口，不反复弹窗。

- **集成方式（接入点）**
  - `SubjectPage.jsx` 头部加 `GradeSwitcher`（年级下拉/分段）；`LearnCenter` 同步入口；`english.note` 在学科页/年级页显性呈现。
  - 复用现有 `state.grade` + `getQuiz(subjectId, state.grade)`（引擎层已就绪）。

- **需补全逻辑 / 错误处理 / 状态管理**
  - 逻辑：年级切换仅派发 `SET_GRADE`，无需清数据。
  - 状态管理：年级已是 `profile` 域字段，持久化已具备。

- **验收要点**：学科页可切换年级且全站内容随之过滤；已学数据保留；英语分龄口径显性标注；切换入口不在全局顶栏。

## 四、优先级与实施节奏建议

| 批次 | 功能 | 定位 | 是否破坏存量 | 依赖 |
|---|---|---|---|---|
| **第三批（地基 + 留存 + 闭环）** | N1 多题型引擎、N2 任务单、N4 错题闭环 | 必修：消除坏 UI、提升次日打开率、补完学习闭环 | 否（N1 仅补分支；N2/N4 纯新增/派生） | N1 先于一切（防潜伏坏 UI） |
| **第四批（差异化护城河）** | N3 诊断报告、N5 互动模式、N6 年级分层 + 科学接入 | 顶级感：家校共育落地点、沉浸互动、合规分龄 | 否 | N3 复用 N4 数据源；N6 复用现有 grade |
| 长期（M2/M3） | 离线 PWA、自适应难度、单元诊断卷/学期报告、自绘动画课 | 可运营与智能化 | 视范围 | 先补数据底座 |

> 建议节奏：**先做 N1（必修，半天内可完成且消除风险）→ N2（留存引擎）→ N4（闭环补全）**，构成第三批；N3/N5/N6 作为第四批冲刺"顶级产品"差异化。

## 六、总结

happy-learning 已走过"接电 + 补半成品"阶段（4.1–4.8 落地）。下一阶段要"打造顶级产品"，重心从**补全**转向**可信度与差异化**：

- **立刻做（地基，防风险）**：N1 多题型引擎（消除潜伏坏 UI）。
- **高杠杆（留存 + 闭环）**：N2 每日任务单、N4 错题↔知识点闭环。
- **护城河（顶级感）**：N3 诊断报告（家校共育核心资产）、N5 互动学习模式、N6 全站年级分层 + 分龄护栏。

以上均不引入新技术栈、不破坏存量，可直接作为第三/四批的验收契约。
